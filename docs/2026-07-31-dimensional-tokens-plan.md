# Dimensional Tokens Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Export `@infra/ui`'s type and radius scale to build-free consumers, then migrate the edge-plane portal off hand-typed dimensional literals onto those tokens, behind a CI guard.

**Architecture:** `scripts/build-tokens.mjs` already copies the whole `@theme` block into `dist/tokens.css`, which edge-plane vendors. Adding eight declarations to `theme.css` — each at Tailwind's *existing default value* — exports the scale without changing anything Tailwind emits, so the four SPA consumers compile byte-identically. The portal then replaces every literal `font-size`/`border-radius` with `var()`, snaps off-grid spacing to the `.25rem` grid, and a new CI script prevents literals returning.

**Tech Stack:** Tailwind v4 `@theme`, vitest, plain CSS custom properties, bash + GitHub Actions, pnpm.

**Design doc:** `docs/2026-07-31-dimensional-tokens-design.md` (this repo).

## Global Constraints

- **Every declared token value must equal Tailwind's default exactly.** The eight values are `--text-xs: 0.75rem`, `--text-sm: 0.875rem`, `--text-base: 1rem`, `--text-lg: 1.125rem`, `--text-xl: 1.25rem`, `--text-2xl: 1.5rem`, `--radius-md: 0.375rem`, `--radius-lg: 0.5rem`. This is what makes the change visually free for the SPAs.
- **Do NOT declare line-height tokens** (`--text-*--line-height`). Tailwind keys them separately; declaring them would change SPA rendering and the portal's line-heights.
- **Do NOT declare `--spacing`.** It is a multiplier base, not a value; no consumer would read it. See the design's Section 1.
- **`--radius` stays untouched** at `0.5rem`. Two primitives use `rounded-[--radius]`.
- **infra-ui commits `dist/`.** Any change to `src/` requires `pnpm build` and committing the regenerated `dist/` in the same change. CI fails otherwise.
- **infra-ui tags are hand-cut.** There is no `release-tag.yml` in this repo — after merging, create the annotated tag manually.
- **Never hand-edit** `infra-ui/dist/tokens.css` or `edge-plane/landing/tokens.css`. Both are generated/vendored artifacts.
- **`.dot`'s `border-radius: 50%` is preserved.** A circle is not a scale value.
- **`letter-spacing: .2rem` stays a literal.** Letter-spacing has no token scale and is not guarded.
- **Confidentiality (both repos' CLAUDE.md):** never commit real data, real account names, or local development filepaths (`/Users/...`). Use relative project paths only.

```ts
// @vitest-environment node
//
// The dimensional scale exported to build-free consumers (edge-plane's static
// portal), which cannot reach Tailwind's defaults the way the SPAs can.
//
// These values are deliberately NOT a redesign: each must equal Tailwind's own
// default, so declaring them changes nothing about what Tailwind emits for the
// four SPA consumers. This test is what makes that claim checkable — including
// after a future Tailwind upgrade, where a changed default should surface here
// rather than silently shifting the portal.
import { readFileSync } from 'node:fs'
import { fileURLToPath } from 'node:url'

const themeCss = readFileSync(fileURLToPath(new URL('./theme.css', import.meta.url)), 'utf8')
const tailwindCss = readFileSync(
  fileURLToPath(new URL('../node_modules/tailwindcss/theme.css', import.meta.url)),
  'utf8',
)

const DIMENSIONAL = [
  '--text-xs',
  '--text-sm',
  '--text-base',
  '--text-lg',
  '--text-xl',
  '--text-2xl',
  '--radius-md',
  '--radius-lg',
]

/** Value of `--name: value;`. The trailing colon keeps `--text-sm` from
 *  matching `--text-sm--line-height`. */
function value(css: string, name: string): string | undefined {
  return new RegExp(`${name}:\\s*([^;]+);`).exec(css)?.[1].trim()
}

test.each(DIMENSIONAL)('%s is declared in theme.css', (name) => {
  expect(value(themeCss, name)).toBeDefined()
})

test.each(DIMENSIONAL)("%s equals Tailwind's default", (name) => {
  const mine = value(themeCss, name)
  const upstream = value(tailwindCss, name)
  expect(upstream).toBeDefined()
  expect(mine).toBe(upstream)
})

test('no line-height tokens are declared — they would change SPA rendering', () => {
  expect(themeCss).not.toMatch(/--text-[a-z0-9]+--line-height:/)
})

test('--spacing is not declared — a multiplier base no consumer reads', () => {
  expect(value(themeCss, '--spacing')).toBeUndefined()
})
```

## Task 5: Add the drift guard (red)

**Files:**
- Create: `scripts/check-no-literal-dimensions.sh`

**Interfaces:**
- Consumes: nothing.
- Produces: `scripts/check-no-literal-dimensions.sh`, exit 0 when clean. Task 8 wires it into CI — deliberately **not** wired here, because it fails until Tasks 6–7 land.

- [ ] **Step 1: Write the guard**

Create `scripts/check-no-literal-dimensions.sh`:

```bash
#!/usr/bin/env bash
# Fails if the portal's hand-written CSS carries a literal dimensional value.
#
# The portal is unprocessed static HTML — nothing compiles it, so nothing
# stops a raw `font-size: .9rem` reappearing. It consumes @infra/ui's exported
# scale via landing/tokens.css instead; this check is what keeps that true.
#
# Scans inline style= attributes as well as the <style> block: the auth-code
# page's OTC size lived in an attribute, exactly where a block-only check
# would miss it.
#
# Not guarded: spacing (per-element padding is legitimately bespoke) and
# letter-spacing (no token scale). border-radius: 50% passes because it is a
# circle, not a scale step — the pattern below only matches rem values.
set -euo pipefail

FILES=(landing/index.html authcode/index.html)
status=0

for f in "${FILES[@]}"; do
  [[ -f "$f" ]] || { echo "missing $f" >&2; exit 1; }
  while IFS= read -r hit; do
    echo "$f:$hit" >&2
    status=1
  done < <(grep -nE '(font-size|border-radius)[[:space:]]*:[[:space:]]*[0-9.]+rem' "$f" || true)
done

if (( status )); then
  cat >&2 <<'MSG'

Literal dimensional values found above. The portal consumes @infra/ui's
exported scale — use var(--text-xs|sm|base|lg|xl|2xl) or
var(--radius-md|lg) instead of a raw rem value.
MSG
  exit 1
fi

echo "ok: no literal font-size/border-radius values in the portal"
```
